Processing coverage: actual course sources and local work

The processing strand contains 21 original notebooks, 42 executable code cells and approximately 17,900 words of instruction. Each lesson includes objectives, an input/output contract, a conceptual explanation, an AI prompt, a short reference implementation, numerical checks, a deliberate mistake, an upstream reading, a real-tool transfer assignment and exit answers. The notebooks are the teaching material; the matrix below records their scope.

This processing strand draws on published lessons and practicals from Berkeley PSYCH214, Dartmouth DartBrains, Oxford FSL, the FreeSurfer workshop, and DIPY. The topic map below links each original notebook to its longer source assignment and expected evidence.

How to complete this strand

Read and execute PR01–PR15 in order, then the PR16–PR19 diffusion block, then PR20–PR21. Budget about 26–35 hours for the 21 notebook lessons, plus the required supervised upstream practical blocks below. These are planning estimates, not institutional credit hours. Each notebook runs from a fresh kernel; code cells within it run in order. No downloaded brain data are needed for the executable core.

Use Goose with the installed Ollama model, or ChatGPT, to explain and propose short code changes. Before running, the student states the units, expected shape, transformation direction and invariant. After running, the student compares a numerical check with a labeled figure and explains a deliberately wrong result. The assistant's explanation is a hypothesis to inspect; the assertions and figures supply the evidence. Model names do not alter the mathematics.

Coverage labels: “executed” below means the original small synthetic/reference calculation ran successfully in our Python environment. “Guided real-tool” means a specific external reading/exercise and required evidence are supplied, but its external software and dataset were not executed in this build. A concept demonstration is not an implementation of an entire established pipeline.

Mesh distances are not FreeSurfer's cortical-thickness algorithm.
Berkeley: slice-time interpolation PR09 · Slice timing Known within-volume offsets, common reference time and interpolation; wrong timing metadata increases error Inspect BIDS SliceTiming/TR and the actual fMRIPrep reference. Multiband metadata and real interpolation are tool-specific.
DartBrains realignment; FSL MCFLIRT PR10 · Motion Correct known translations; dropout persists; rotation-to-distance FD unit conversion Inspect six realignment traces and registered movies/overlays. No claim that rigid motion correction removes spin history or recovers dropout.
FSL registration unwarping; FDT TOPUP PR11 · Susceptibility distortion Known phase-encoding distortion, inverse remapping, wrong sign and unrecoverable signal loss Read phase-encoding direction/readout metadata and inspect corrected EPI with structural boundaries. This is not a field estimation implementation.
DartBrains preprocessing: smoothing PR12 · Spatial smoothing Convert 6 mm FWHM to axis-specific voxel sigmas; mask-edge attenuation versus normalized convolution Record kernel units, mask, surface/volume choice and effective resolution. Increased smoothness is not new spatial information.
DartBrains: sampling, Fourier and filters PR13 · Temporal filters TR-dependent Nyquist, aliasing, measured pass/stop amplitudes and wrong sampling frequency Compare configured filter/design policy to task frequencies and run duration. Toy steady signals do not establish an optimal cutoff.

DartBrains preprocessing QC; fMRIPrep report/confounds PR15 · QC and censoring FD and DVARS detect two affected frames; aligned row deletion retains original acquisition times Write a reasoned censoring rule, inspect remaining duration/design and report participants lost. No universal QC threshold is claimed.
FSL FDT; DIPY gradient tables PR16 · Diffusion gradients b-values/directions with b0 entry; simultaneous frame rotation preserves signal; volume/gradient mismatch fails Match gradients to ordered DWI volumes and use corrected gradients after motion/eddy processing. Coordinate conventions must be documented.
DIPY MP-PCA/Gibbs; FSL EDDY PR17 · Diffusion preprocessing Low-rank denoising versus rank loss; Fourier truncation produces ringing; taking absolute values is not Gibbs correction Run actual MP-PCA/Gibbs examples and a TOPUP/EDDY QC practical in their environments. Local rank truncation is not MP-PCA or EDDY.
DIPY DTI; FSL DTIFIT PR18 · Diffusion tensor Full-rank six-parameter noiseless tensor fit; eigenvalues, MD/FA; wrong b units alter MD while FA remains unchanged Fit/check an actual tensor with S0 handling, mask, noise-aware fitting and residual maps. Required upstream practical blocks for full applied coverage

The small labs establish understanding. To claim practical processing proficiency, complete these supervised blocks using the linked courses' actual tools and authorized data. Record uncompleted blocks as guided, not executed. Their current status in this delivered repository is not executed.

  1. Geometry and fMRI alignment — 4–6 hours. Work through the FSL registration practical's affine estimation, application to another image, inverse mapping and nonlinear sections. Add the DartBrains realignment/smoothing sections and inspect one fMRIPrep report. Submit before/after overlays in three planes, one transform-direction diagram, interpolation choices, phase-encoding metadata, a motion/QC decision and a preserved original image. Check whether a visually attractive overlay conceals a left/right or field-of-view error.
  2. Structural processing and morphometry — 4–6 hours. Complete the FSL structural practical's FAST bias/segmentation and VBM portions, then inspect the SIENA/SIENAX or equivalent longitudinal section. Submit estimated bias field, brain-mask boundaries, hard and fractional segmentations, physical volume calculation and modulation convention. For FIRST or lesion mapping extensions, record those as separate optional methods; a successful FAST run does not validate them.
  3. Cortical surfaces — 3–5 hours plus reconstruction compute. Follow the FreeSurfer volume/surface and reconstruction-QC workshop sections. Use the workshop's prepared outputs where permitted so the student can inspect rather than wait for reconstruction. Submit white/pial overlays, one defect diagnosis, a region table with units and a longitudinal comparison plan. Do not hand-edit clinical surfaces without expert supervision.
  4. Diffusion reconstruction and tracking — 5–8 hours plus compute. Follow FSL FDT's metadata, TOPUP/EDDY, QC and DTIFIT portions. Complete DIPY's tensor and crossing/tracking examples in the documented DIPY environment. Submit gradient/volume consistency checks, correction diagnostics, MD/FA/residual maps and at least two tracking choices with their consequences. TBSS's processing and group-inference sections are an extension that requires the design/statistics strand; streamline visualization alone is insufficient.
  5. Reproducible execution and report defense — 3–4 hours. Read the three vendored Nipype chapters, then use the upstream environment to run a small authorized workflow. Preserve inputs, parameters, software/container versions, transform files, command logs and QC judgments. Repeat one parameter change and identify which nodes legitimately rerun. Explain a failure rather than suppressing its log. Present the provenance alongside an actual generated report.

These estimates add roughly 19–29 hours of guided work, excluding downloads and heavy reconstruction. Together with the notebooks this is a substantial processing strand, not the entirety of neuroimaging graduate training. Mentoring and actual dataset/tool access are necessary for the external blocks.

What remains outside or beyond this strand

Quantitative relaxometry, spectroscopy, ASL perfusion, PET processing, EEG/MEG source reconstruction, histology registration, lesion-specific validation, advanced cortical longitudinal modeling, and complete CSD/probabilistic tractography or TBSS inference are not implemented by these notebooks. Some are present as optional upstream extensions; they require additional method-specific teaching. Full N4/BET/FAST/FLIRT/FNIRT/MCFLIRT/TOPUP/EDDY/FreeSurfer/fMRIPrep implementations remain the established tools used by the guided practicals. We do not substitute a few NumPy lines for those validated software systems.

Reproducibility, compatibility and borrowed materials

Local verification passed 21/21 notebooks and 42/42 code cells in fresh Python namespaces with Agg plotting; see processing_verification.json. The root integration additionally executes notebook kernels and produces rendered outputs. Local testing used Python 3.14.7, NumPy 2.5.3, SciPy 1.18.1, Matplotlib 3.11.2, NiBabel 5.4.2 and scikit-learn 1.9.1. These exact versions are evidence of a tested environment, not a claim that older versions were exhaustively tested.

All lessons need NumPy/SciPy/Matplotlib; PR01 also needs NiBabel; PR06/PR14 use scikit-learn. The source uses Python's graphlib (Python >=3.9) and FastICA(whiten='unit-variance') (scikit-learn >=1.1). Those are identifiable API floors, not a supported installation matrix; use the course environment for a known configuration. No core lesson needs Nipype, FSL, FreeSurfer, DIPY, Torch, network access, model weights or a patient's scan.

The third-party directory contains three original Nipype .ipynb files and one original DartBrains Marimo .py notebook, with full applicable licenses, immutable commit references and SHA-256 records. They are actual upstream teaching material, not locally invented substitutes. They are not part of automated execution and are not claimed to run as isolated files without their upstream environment/assets. Public proprietary/unlicensed course text, participant datasets and images have not been mirrored. Original lessons use original prose and code with links to the material that informed their scope.
